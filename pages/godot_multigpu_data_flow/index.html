Godot マルチ GPU 分散描画 — データフロー詳細図

本ドキュメントは、Godot エンジン上で異種 GPU（NVIDIA RTX 2080 Ti + GTX 1080）を組み合わせた分散描画システムのデータフローを図解するものである。VR 環境において特定メッシュの描画を 2 枚目の GPU にオフロードし、Win32 共有メモリを介してフレームデータを転送、深度テスト付きアルファ合成で最終映像を統合する。

最終アーキテクチャ: システム全体のデータフロー

本システムは、メインプロセス（RTX 2080 Ti で通常シーンを描画）とサブプロセス（GTX 1080 でオフロード対象メッシュを描画）の 2 つの Godot インスタンスで構成される。両プロセスは OS のプロセス境界で完全に分離されており、Win32 共有メモリ（CreateFileMappingW / MapViewOfFile）でデータを交換し、Win32 Auto-Reset Event（CreateEventW / SetEvent / WaitForSingleObject）でフレーム単位の書き込み完了通知を行う。

サブプロセスは、GPU で描画したカラー（RGBA16F）とデプス（float32）を非同期 readback で CPU へ回収し、共有メモリのダブルバッファへ書き込んだ後、イベントをシグナルする。メインプロセス側では、専用のワーカースレッドがイベント待機 → memcpy で永続ステージングバッファへ転送 → フラグ更新を行い、メインスレッドの _process() はフラグを確認して Vulkan DMA コマンド（vkCmdCopyBufferToImage）を投入するだけで済む。最終合成は CompositorEffect の Compute Shader が担い、メインシーンとサブシーンのカラー・デプスをピクセル単位で比較統合する。

深度合成パイプライン: メインシーンとサブシーンの統合

メインプロセスが描画した通常シーンと、サブプロセスが描画したオフロード対象メッシュを、最終的にピクセル単位で合成する処理の詳細を示す。

合成は Godot の CompositorEffect として Compute Shader（compositor_effect_ipc.glsl）で実行する。4 つの入力テクスチャ（メインのカラーとデプス、サブのカラーとデプス）を受け取り、各ピクセルについて以下の手順で処理する。

  1. 透明画素の早期棄却: サブ側のアルファ値が 0.001 以下であれば、そのピクセルにはサブ側の描画が存在しないため、メイン側のカラーをそのまま出力する
  2. 深度比較（Reverse-Z）: Godot は Reverse-Z 深度バッファ（近い物体ほど値が大きい）を使用するため、d_sub > d_main のときサブ側が手前と判定する
  3. アルファ合成（Over 演算）: サブが手前の場合、pre-multiplied alpha Over 演算 C_out = C_sub + C_main × (1 - A_sub) で半透明を含む自然な合成を行う
